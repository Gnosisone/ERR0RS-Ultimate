## Known issues deferred to future sessions

### 1. gemma3:1b LLM timing out at 20s every call
**Evidence:** Multiple `LLM suggest failed: Command timed out after 20 seconds` in launcher log.
**Hypotheses:**
- Pi 5 RAM pressure — `ollama list` shows 5 models (gemma3:1b, err0rs-qwen, llama3.2:3b, err0rs-pi5, qwen2.5-coder:7b) totaling ~17 GB on 8 GB hardware
- Ollama context bloat after long uptime
- Possible ollama version regression since 2026-05-20 stress tests
**Investigation when ready:**
- After cold Pi boot, `time ollama run gemma3:1b "Reply OK"` — measure baseline
- `ollama ps` to see which models are loaded into RAM
- Consider `OLLAMA_KEEP_ALIVE=2m` to free unused model weights
- Re-run the stress-test suite from `docs/STRESS_TESTS/FINDINGS_2026-05-20.md`

### 2. Operator Brain ran nmap twice with `target: null`
**Evidence:** Launcher log shows `tools_run: ["nmap", "nmap"]` with `target: null`.
**Likely cause:** Brain doesn't receive the onboarding target context when invoked via suggestion-card click. Mission Coach knows the target (`localhost` for Juice Shop) but doesn't pass it through.
**Fix sketch:** When mission-active, the Operator Brain `_run_tool()` should default `target` from `_obPayload.first_mission_steps[_currentStep].command` (parse it out) rather than allowing null.

### 3. Mission 02 (sql_basics) has empty `steps[]` in `onboarding.py`
**Status:** Backend feature gap, always documented as "expanded in session". Not a regression.
**Plan:** After Mission 01 is rock-solid, design the 3-step SQL injection mission (likely sqlmap on Juice Shop login form).

### 4. Tooltip system origin
**Curiosity:** the `[data-help]:hover::after` system works great but isn't documented anywhere. If we add more tooltips later, the `data-help-pos="below"` opt-in is the established pattern.

### 5. WebSocket 426 errors flooding the log
**Evidence:** `[ERR0RS] ERROR opening handshake failed ... missing Connection header` spam in `/tmp/err0rs_live.log`.
**Cause:** Something (probably Firefox tab auto-refresh or browser HEAD requests) is hitting port 8766 without WS upgrade.
**Impact:** Cosmetic only — doesn't affect functionality. Worth filing as a hygiene cleanup in a future session.
